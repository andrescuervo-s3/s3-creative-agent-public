disable-model-invocation — What It Means

Should Claude decide when to activate the Strategy Brief skill, or should only the user trigger it?

How skill activation works
Default: Claude CAN auto-activate
disable-model-invocation: false (or omitted)
USER SAYS:
"I need to formalize the strategy for the Popok project"
↓ Claude reads the description, decides this matches ↓
CLAUDE DOES:
Automatically loads s3-strategy-brief SKILL.md and starts the flow
Good for: Skills that are safe to trigger automatically. Like the foundational brief — if someone says "foundational brief," Claude should just start it.
Disabled: ONLY user can trigger
disable-model-invocation: true
USER SAYS:
"I need to formalize the strategy for the Popok project"
↓ Claude does NOT auto-activate — user must explicitly type ↓
USER TYPES:
/s3-creative-agent:s3-strategy-brief
Good for: Skills with side effects you want to control timing on — deployments, sending messages, destructive operations.
For the Strategy Brief: Since the brief selector already routes users here, and the foundational brief uses auto-activation with trigger phrases ("strategy brief", "strategic brief", etc.), I'd recommend keeping it auto-activatable (default). The brief selector + trigger phrases in the description handle routing. There's no risk of accidental activation because the TRIGGERS list is specific.
A

Keep auto-activatable (Recommended)

Claude activates when user says "strategy brief" or similar trigger phrases. Same pattern as the foundational brief. Brief selector also routes here.

B

User-trigger only

User must type the slash command or be routed by the brief selector. Claude never auto-activates even if the conversation is clearly about strategy.
