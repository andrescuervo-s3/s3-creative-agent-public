Strategy Brief Skill — Design Spec

Skill: s3-strategy-brief | Stage 2 | Output: .docx

Purpose

Formalizes foundational facts + creative call outputs into strategic recommendations. First document where creative direction exists. Sits between Foundational Brief (facts) and Creative Briefs (execution).

Who: S3 internal team. When: After creative call, after Foundational Brief exists.

Interaction Model: Structured Top, Freeform Bottom

Phase 1
Ingestion
Structured, automatic
Phase 2
Auto-Summary
Agent synthesizes
Phase 3
Conversation
Guided + freeform
Phase 4
Pressure Test
Gate + .docx output

Phase 1: Ingestion

Required Inputs

  • Foundational Brief (.docx) — uploaded or found on Drive. Agent extracts "Created" date from cover (1.1) for time filtering. Fallback: (1) Created field, (2) Last Updated field, (3) file mod date, (4) ask user.
  • Work Agreement — any readable format. Agent extracts line items and presents for user confirmation: "Here are the line items I found. Is this complete?"

Automatic Scans (since Foundational Brief date)

  • Slack — threads mentioning client name (new messages since date)
  • Google Drive — files created or modified since date
  • Google Docs — documents modified since date
  • Local Cowork folder — any documents in workspace

Note: Gmail not currently configured as connector. User uploads email content manually.

After Scans

"Anything else to add? Verbal notes, transcripts, attachments, data exports?"

Agent presents catalog of everything found. Asks: "Does this cover everything, or do you have more to add before I start building the summary?" Proceeds only after user confirms.

Phase 2: Auto-Summary

Agent synthesizes all ingested material into first pass at the full skeleton, presented as one message:

  • Brand Strategy (1.0) — pulls forward foundational facts, drafts initial versions as starting points
  • Channel Strategies (2.0) — drafts summaries for channels with material; "No input yet" for channels without
  • Scope flags — Work Agreement line items mapped to sections; gaps called out
  • Bright Idea (1.7) — surfaced if found in sources, otherwise "To be developed"

Phase 3: Conversation

Brand Strategy (1.0) — Guided
Agent walks through in order: Positioning → Mission → Value Prop → Audiences → Voice & Tone → Messaging → Bright Idea.

Lightweight approval per subsection. User can defer ("come back to this"). Agent tracks deferred items and raises them before transitioning to channels and again before pressure test.
Channel Strategies (2.0) — Freeform
Agent asks "Where do you want to start?" User drives.

Agent listens, organizes riffing into sections, asks follow-ups, flags scope expansion inline, spins up research agents on demand, handles section-jumping. Prompts about untouched sections when conversation winds down.

Research Agents (On-Demand)

  • Check Foundational Brief first before researching
  • Research Logs presented inline (3-8 entries with live links)
  • Same validation rules and confidence scoring as Foundational Brief
  • Key distinction: Facts get confidence scores. Strategy does not. "65% of the market is millennials" = scored. "We should target millennials" = strategic decision, no score.

Phase 4: Pressure Test

Checks run sequentially. User resolves flags from each before moving to the next.

1. Audience Coverage
Every foundational audience has a communication angle and appears in at least one channel strategy
2. Scope Coverage
Every Work Agreement line item maps to a channel section
3. Strategic Coherence
Bright Idea threads through channels. Intentional divergence OK, unexplained divergence flagged
4. Feasibility Notes
Timeline/resource/dependency observations collected. Not a blocker.

After all checks pass → Scope Expansion Opportunities collected in 3.2 → .docx generated

Scope Flagging

Inline: Ideas outside Work Agreement live in their relevant section with a visual callout (orange left border, light gray background, italic).

Collected: Section 3.2 aggregates all flags as a checklist — the last thing read before moving to creative brief.

Key Distinctions

  • 2.5 S3 Media Strategy = production brief (what to shoot, where, talent, locations)
  • 2.6 Creative Direction = design system (visual language across all touchpoints)
  • 2.6 informs 2.5 (shoot should reflect design system), but different scopes

Per-Client Project Context

Every skill run creates/updates CLAUDE.md and MEMORY.md in the client's project folder. Contains: client name, key people, documents produced, decisions, Work Agreement items, connector findings.

Output

  • .docx, Open Sans, per s3-docx-styles.md
  • Always DRAFT in v1 (FINAL stamping comes with future Finalize mode)
  • Heading mapping: 1.0 = H1, 1.1/2.1 = H2, 2.1.1 = H3, sub-fields = H4
  • Built incrementally (session recovery: progress saved as sections settle)
  • No em dashes, no code/HTML

Gotchas

  1. Do NOT hallucinate strategic recommendations. Agent organizes what user provides.
  2. Do NOT confuse riffing with finalized direction. Track latest position, confirm when changed.
  3. User-stated strategy does not get confidence scores. Only researched facts.
  4. The Bright Idea can be plural (one master OR channel-specific ideas).
  5. Scope flags are additive, not blocking. Visibility, not gatekeeping.
  6. Do NOT research what the Foundational Brief already covers.
  7. Work Agreement line items are fuzzy big buckets. Match by category, ask when ambiguous.
  8. Document section order is fixed; conversation order is not.
